## 2. 产品定义

CyberMonitor 是一款基于 ESP32 的独立式物理监控终端。系统通过 Wi-Fi 接入局域网，向 Prometheus 发起标准 HTTP API 请求，获取主机运行指标，并通过 8 个机械模拟直流电压表组成的 2x4 矩阵进行实时显示。系统同时集成 LCD 2004 状态屏与本地 Web 配置页面，形成完整的配网、运行、监视闭环。

## 3. 产品目标

### 3.1 功能目标

1. 实现 8 路系统监控指标的实时物理显示。
2. 实现基于 Prometheus 的标准化数据接入。
3. 实现首次上电配网与运行中状态可视化。
4. 实现设备脱离电脑独立运行。

### 3.2 体验目标

1. 仪表读数具备连续、平滑、机械阻尼感。
2. 配网流程适合手机浏览器直接完成。
3. LCD 屏幕持续反馈网络状态、目标地址、抓取结果与时延。

## 4. 系统组成

| 模块 | 说明 |
| --- | --- |
| 主控模块 | ESP32 负责网络连接、配置管理、数据请求、JSON 解析、PWM 输出 |
| 仪表显示模块 | 8 个机械直流电压表组成物理矩阵 |
| 保护模块 | 每路仪表并联续流二极管，吸收线圈反向电动势 |
| 状态显示模块 | LCD 2004 负责显示系统状态与运行信息 |
| 配置服务模块 | ESP32 内置 Web Server 提供 Wi-Fi 与 Prometheus 参数配置页面 |
| 数据采集模块 | 通过 HTTP GET 访问 Prometheus API |
| 存储模块 | 使用 Preferences 保存持久化配置 |

## 7. 接线拓扑规格

### 7.1 电源连接

1. 5V 电源接入 ESP32 的 `VIN` 或 `5V` 引脚。
2. 5V 电源同时接入 LCD 的 `VCC` 引脚。
3. 所有模块共用统一 `GND` 地线。

### 7.2 I2C 连接

| ESP32 引脚 | LCD 引脚 |
| --- | --- |
| GPIO 21 | SDA |
| GPIO 22 | SCL |

### 7.3 仪表连接

8 个表盘正极分别连接以下 GPIO：

`13, 14, 15, 25, 26, 27, 32, 33`

8 个表盘负极统一接系统 `GND`。

### 7.4 二极管连接

每个电压表的正负极之间并联一个续流二极管。

| 二极管端 | 连接位置 |
| --- | --- |
| 负极（带白环） | 电压表正极 |
| 正极 | 电压表负极 |

## 8. 软件功能规格

### 8.1 配置管理模块

系统使用 Preferences 作为非易失性存储，命名空间定义为 `config`。

配置项包含：

| 配置项 | 说明 |
| --- | --- |
| wifi_ssid | Wi-Fi 名称 |
| wifi_password | Wi-Fi 密码 |
| prometheus_host | Prometheus 服务器地址 |
| prometheus_port | Prometheus 端口 |
| fetch_interval_ms | 数据抓取周期 |

### 8.2 Web 配网模块

系统内置 HTTP 配置页面，页面承载以下输入项：

1. Wi-Fi 名称
2. Wi-Fi 密码
3. Prometheus Server IP
4. Prometheus Port

用户提交后，系统执行以下流程：

1. 写入 Preferences
2. 返回保存结果页面
3. 执行设备重启
4. 进入运行模式

### 8.3 状态显示模块

LCD 2004 用于显示系统运行信息。

配网模式显示内容：

- 第 1 行：`SYS: Setup Mode`
- 第 2 行：`Connect AP:`
- 第 3 行：`CyberMonitor-Setup`
- 第 4 行：`IP: 192.168.4.1`

运行模式显示内容：

- 第 1 行：`SYS: Running`
- 第 2 行：`IP: [Local IP]`
- 第 3 行：`Tar: [Prometheus IP]`
- 第 4 行：`Fetch: [Status] [Delay]`

### 8.4 数据请求模块

系统以固定周期向 Prometheus 发起 HTTP GET 请求。请求路径采用 Prometheus 标准查询接口。查询内容采用单条组合 PromQL 语句承载 8 个指标。

### 8.5 JSON 解析模块

系统使用 ArduinoJson 进行反序列化。解析策略采用 `StaticJsonDocument` 与 Filter，仅保留目标 `value` 节点。每路指标解析结果转换为浮点值，供后续显示映射使用。

### 8.6 表盘驱动模块

系统初始化 8 个 LEDC 通道。每个通道绑定一个仪表 GPIO。指标数据经归一化与比例映射后，转换为 `0-255` PWM 占空比。驱动模块维护当前值和目标值两个状态，按固定步进周期推进占空比，形成平滑机械阻尼效果。

## 9. 工作状态机

### 9.1 模式 A：AP 配网模式

触发条件：

1. 首次开机
2. 已保存配置为空
3. Wi-Fi 连接流程未建立有效连接

执行流程：

1. 启动 AP 热点 `CyberMonitor-Setup`
2. 启动本地 Web Server
3. LCD 显示配网引导信息
4. 用户通过浏览器打开 `192.168.4.1`
5. 用户填写配置参数并提交
6. 系统保存配置并重启

### 9.2 模式 B：正常运行模式

触发条件：

1. 配置信息完整
2. Wi-Fi 连接成功

执行流程：

1. 读取本地配置
2. 连接指定 Wi-Fi
3. LCD 显示本机 IP 与目标地址
4. 周期性向 Prometheus 发起请求
5. 解析 8 个指标值
6. 更新 LCD 抓取状态
7. 驱动 8 路仪表执行平滑偏转

## 10. 指标映射规格

### 10.1 百分比类指标

适用指标：

1. CPU Load
2. GPU Load
3. RAM Usage

映射规则：

0-100 映射到 PWM 0-255

### 10.2 温度类指标

适用指标：

1. CPU Temp

建议量程：

0-100 摄氏度映射到 PWM 0-255

### 10.3 吞吐类指标

适用指标：

1. Net Up
2. Net Down
3. Disk Read
4. Disk Write

建议策略：

采用预设上限值进行线性映射。上限值支持后续在配置中扩展为可调参数。

## 13. 交互流程规格

### 13.1 首次使用流程

1. 上电启动
2. 设备广播 `CyberMonitor-Setup`
3. 用户连接热点
4. 浏览器访问 `192.168.4.1`
5. 填写 Wi-Fi 与 Prometheus 参数
6. 提交并重启
7. 进入运行模式

### 13.2 日常运行流程

1. 设备自动连接已保存 Wi-Fi
2. 系统周期抓取 Prometheus 数据
3. LCD 实时显示抓取状态
4. 8 路表盘持续同步物理反馈

## 14. 验收标准

### 14.1 硬件验收

1. 8 个表盘全部完成独立偏转。
2. LCD 2004 正常显示 4 行状态信息。
3. AP 模式热点可稳定广播。
4. 二极管安装方向与规格符合设计要求。

### 14.2 功能验收

1. 首次上电进入配网模式。
2. 提交配置后设备完成重启并连接目标 Wi-Fi。
3. 设备可成功访问 Prometheus API。
4. 设备可正确解析 8 路指标值。
5. 表盘偏转与指标变化保持同步。
6. 指针运动具备平滑连续效果。
7. LCD 可显示抓取结果与请求时延。

### 14.3 稳定性验收

1. 连续运行 24 小时保持稳定抓取。
2. 断电重启后自动恢复配置并进入运行模式。
3. 网络重连后系统恢复数据抓取流程。

## 15. 后续扩展方向

3. 支持 PromQL 文本可视化配置。
4. 支持抓取周期调整。

## 16. 项目结论

CyberMonitor 以 ESP32 为核心控制器，以 Prometheus 为标准数据源，以 8 路机械指针表盘为核心可视化载体，构建出一套具备网络接入、参数配置、状态显示、数据抓取、平滑驱动能力的独立式物理监控终端。该系统同时满足展示性、工程性、可扩展性与长期运行需求，适合作为桌面监控设备、实验性开源硬件项目与赛博工业风物理观测终端。
