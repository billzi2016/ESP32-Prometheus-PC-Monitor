# CyberMonitor 测试计划

## 1. 文档目标

本文件定义 CyberMonitor 首版固件与硬件联调的测试范围、测试项目、执行顺序和验收标准，用于保证配网、抓取、显示和驱动链路完整可用。

## 2. 测试范围

本轮测试覆盖以下内容：

1. 硬件接线正确性
2. 上电启动流程
3. AP 配网流程
4. Wi-Fi 连接流程
5. Prometheus 连通性
6. 指标解析流程
7. LCD 状态显示
8. 8 路表盘驱动
9. 断电重启恢复
10. 长时间稳定性

## 3. 测试前置条件

1. ESP32、LCD、8 路表盘、二极管和电源完成接线
2. Prometheus 服务已可访问
3. Prometheus 侧可查询 `windows_exporter` 的真实指标
4. 手机或电脑可连接 `CyberMonitor-Setup`
5. 串口工具可用于观察启动日志

## 4. 测试阶段

| 阶段 | 名称 | 目标 |
| --- | --- | --- |
| Stage 1 | 硬件静态检查 | 确认接线、极性和供电无误 |
| Stage 2 | 启动与配网测试 | 确认 AP、配置页、保存与重启流程 |
| Stage 3 | 运行链路测试 | 确认 Wi-Fi、Prometheus、解析与 LCD 状态正常 |
| Stage 4 | 表盘驱动测试 | 确认 8 路通道都能平滑偏转 |
| Stage 5 | 异常与恢复测试 | 确认掉线、重启、配置保留和长稳表现 |

## 5. 测试用例

### 5.1 硬件静态检查

| 用例编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| HW-01 | 检查 5V 和 GND 接线 | 电源极性正确，无反接 |
| HW-02 | 检查 LCD I2C 接线 | `GPIO 21 -> SDA`，`GPIO 22 -> SCL` |
| HW-03 | 检查 8 路表盘正极接线 | 与文档定义的 GPIO 一致 |
| HW-04 | 检查 8 路表盘负极接线 | 全部共地 |
| HW-05 | 检查 8 个二极管方向 | 白环端连接表盘正极 |

### 5.2 启动与配网测试

| 用例编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| BOOT-01 | 首次上电启动 | 设备进入 AP 模式 |
| BOOT-02 | 热点广播检查 | 可见 `CyberMonitor-Setup` |
| BOOT-03 | 访问配置页面 | 浏览器可打开 `192.168.4.1` |
| BOOT-04 | 配置项展示 | 页面可填写 Wi-Fi、Prometheus Host、Port、Prometheus Instance、Fetch Interval |
| BOOT-04A | 两段式向导检查 | 页面先接 Wi-Fi，再根据 IP 和子网掩码推导地址前缀 |
| BOOT-05 | 提交配置 | 页面返回保存成功信息 |
| BOOT-06 | 保存后重启 | 设备自动重启 |

### 5.3 运行链路测试

| 用例编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| RUN-01 | Wi-Fi 连接成功 | LCD 显示本机 IP |
| RUN-02 | 目标地址显示 | LCD 显示 Prometheus Host 和 Port |
| RUN-02A | HTML 前缀推导 | 页面可自动给出局域网地址前缀，用户只需补最后一段 |
| RUN-03 | Prometheus API 可访问 | 抓取状态显示成功 |
| RUN-04 | 抓取延迟显示 | LCD 第四行显示 `Fetch: OK` 与延迟 |
| RUN-05 | 抓取失败反馈 | LCD 第四行显示 `Fetch: ERR` |

| MET-02 | CPU Temp 返回 | CH1 表盘响应，前提是 `thermalzone` collector 有数据 |
| MET-03 | GPU Load 返回 | CH2 表盘响应，前提是 `gpu` collector 有数据 |
| MET-04 | RAM Usage 返回 | CH3 表盘响应 |
| MET-05 | Net Up 返回 | CH4 表盘响应 |
| MET-06 | Net Down 返回 | CH5 表盘响应 |
| MET-07 | Disk Read 返回 | CH6 表盘响应 |
| MET-08 | Disk Write 返回 | CH7 表盘响应 |

### 5.5 表盘驱动测试

| 用例编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| GAUGE-01 | 单路低值输入 | 指针小幅偏转 |
| GAUGE-02 | 单路高值输入 | 指针接近满刻度 |
| GAUGE-03 | 单路快速变化 | 指针平滑步进变化 |
| GAUGE-04 | 多路同时变化 | 8 路均可独立更新 |
| GAUGE-05 | AP 模式下复位 | 表盘目标值回到低位 |

### 5.6 异常与恢复测试

| 用例编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| REC-01 | 断开 Wi-Fi | 系统尝试重连，失败后可回到 AP 模式 |
| REC-02 | Prometheus 关闭 | LCD 显示抓取错误 |
| REC-03 | 断电重启 | 配置仍保留 |
| REC-04 | 恢复网络 | 系统可恢复抓取 |
| REC-05 | 连续运行 24 小时 | 不出现死机、明显漂移或失联 |

## 6. 测试记录建议

每轮测试建议记录以下信息：

1. 固件版本
2. ESP32 板型
3. Prometheus 地址
4. Exporter 类型
5. 测试时间
6. 实际结果
7. 异常现象
8. 是否通过

## 7. 验收标准

满足以下条件时，可判定首版系统通过基础验收：

1. 首次上电可进入 AP 模式
2. 配置可保存并重启
3. 正常模式下可连上 Wi-Fi
4. 可访问 Prometheus API
5. LCD 可显示运行状态与抓取状态
6. 8 路表盘均可根据指标变化响应
7. 指针更新过程平滑连续
8. 断电后配置保持不丢失

## 8. 后续测试扩展

1. 不同表盘型号的量程校准
2. 不同 Wi-Fi 环境的稳定性测试
3. 多种 exporter 口径下的 metric 兼容性测试
4. 长时间高频抓取下的内存占用观察
