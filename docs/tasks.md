# CyberMonitor 开发任务拆解

## 1. 文档目标

本文件用于定义 CyberMonitor 的开发任务结构、阶段目标、交付内容与验收标准。任务拆解面向固件实现、硬件装配、联调验证与交付准备。

## 2. 总体阶段划分

| 阶段 | 名称 | 目标 |
| --- | --- | --- |
| Phase 1 | 文档与方案确认 | 明确产品定义、接线方案、指标映射与运行流程 |
| Phase 2 | 硬件准备与连线 | 完成主控、LCD、表盘、二极管、电源的物理连接 |
| Phase 3 | 基础固件框架 | 完成启动流程、配置存储、状态机结构 |
| Phase 4 | 配网与配置页面 | 完成 AP 模式、Web 配置页面、参数持久化 |
| Phase 5 | 数据拉取与解析 | 完成 Prometheus API 请求、JSON 过滤解析、指标值提取 |
| Phase 6 | 仪表驱动与平滑算法 | 完成 8 路 PWM 输出、数据映射、平滑步进控制 |
| Phase 7 | 联调与验收 | 完成整机运行测试、异常验证与验收记录 |

## 4. 模块验收条件

### 4.1 硬件模块

1. 所有模块正常供电。
2. 所有地线共地完整。
3. I2C 屏幕显示稳定。
4. 8 路表盘接线与 GPIO 映射一致。
5. 8 个续流二极管方向正确。

### 4.2 配网模块

1. 热点名称正确广播。
2. 手机可连接热点。
3. 浏览器可访问配置页。
4. 提交参数后可完成保存与重启。

### 4.3 数据模块

1. 设备可成功连接目标 Wi-Fi。
2. 设备可成功访问 Prometheus。
3. 返回数据可被稳定解析。
4. 抓取异常时 LCD 可显示失败状态。

### 4.4 驱动模块

1. 8 路 PWM 全部可输出。
2. 指针变化平滑连续。
3. 数据更新时无明显阶跃抖动。
4. 数值变化与表盘偏转方向一致。

## 5. 开发优先级

| 优先级 | 内容 |
| --- | --- |
| P0 | 硬件接线、配网、Prometheus 抓取、8 路驱动 |
| P1 | LCD 状态信息完善、平滑步进算法调优 |
| P2 | 参数扩展、自定义映射、后续可视化增强 |

## 6. 风险与关注点

| 风险点 | 说明 |
| --- | --- |
| 表盘量程不匹配 | 非 3V 或 3.3V 表盘会影响显示范围 |
| 线圈反向电动势 | 未安装续流二极管会增加 GPIO 风险 |
| Wi-Fi 不稳定 | 会导致抓取中断与状态切换 |
| PromQL 设计不合理 | 会增加解析复杂度与请求成本 |
| JSON 体积过大 | 可能触发 ESP32 内存压力 |
| 平滑步进过快或过慢 | 会影响机械视觉效果 |
